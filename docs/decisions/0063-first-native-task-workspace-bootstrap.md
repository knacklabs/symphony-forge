# One-task workspace bootstrap through existing gates

## Context

Decision0059 requires the task workspace before detailed task planning. The
current `task start` implementation needs a saved task plan and grill before
it can create that workspace. Repairing that command first would itself need
an admitted writer. Decision0058 permits isolated native preparation but does
not explicitly change this ordering.

On10 September2026 the user said, “You have approval for all. Now don’t stop.”
This record applies that standing authorization to the minimum in-scope
bootstrap transition. It does not claim the user separately answered a question
about this record or replace any technical gate.

## Decision

For only the first native foreground support task in FORGE-COORD-1, permit the
current task-start ordering: author, independently grill and approve its real
contract in the planning checkout, then let `forge task start` create the real
task worktree and protected task identity. After exact bounded target
preparation, finish the task's detailed plan there and freshly ground, record,
grill and approve that target contract before stage start and native delegation.
The source approval is history, never fresh target proof.

The first task lands native write hooks and legitimate process-bound worker
admission together, including its own complete proof-consumer repairs. Only
original, explicitly allocated preparation may be imported before admission;
new product implementation remains delegated. The workspace-first command
change retains its named delivery owner; subsequent tasks use it once shipped.

## Consequences

- This amends only0059's pre-workspace planning prohibition for that first
  bootstrap task. Every other0058/0059 requirement remains in force.
- Preserve genuine artifact approvals, actual task ownership, target schemas,
  scope, process identity, launch/completion, tests, verification, full review,
  review limits, normal task PRs and real predecessor markers on trunk.
- Use existing task-start and recorders. No placeholder plan or grill, manual
  protected-state write, evidence transfer, runtime-source framework, `--trunk`
  bypass, coordinator-write exception or Claude fallback is introduced.
- Publish the already approved planning canon separately, with complete
  independent document review. It carries no implementation claim or task
  marker. Every prepared product byte remains owned by its complete code task.
