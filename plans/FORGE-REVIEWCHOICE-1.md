# A person can skip the model review, and forge.toml sets the review rounds

2 parts · Risks: none one-way · New moving parts: two options on `forge close`, two `forge.toml` settings, two small modules

## What changes for you

- A named person can close an item without the model review. Their name and reason show on the pull request. Tests, CI, the design checks and the merge step still run.
- Close refuses the skip when a review has already blocked the item. Agents use the skip only when a person asks for it.
- Two forge.toml settings set the rounds before Forge asks the person: one for a plan's cold read and one for a task's review, each one or two, both two by default. Fixes keep one review round. At the limit Forge still asks for one more round, split or accept.
- This replaces the rule that every item gets a model review (decision 0092); the owner chose this on 6 Nov 2026.
- New client repos get the skip and the settings at init. Existing client repos get them on upgrade.

## Why

Small changes such as version bumps, docs and generated files wait for a model review that adds little, and no close option skips it. The round limits are fixed in code, so a team cannot choose one round for its cold reads or its task reviews.

## Done when

1. **Close with a named person and a reason skips only the model review, and the name and reason show on the pull request.**
2. **Close refuses the skip after a blocking review, and tests, CI, the design checks and the merge step still run on a skipped item.**
3. **forge.toml sets one or two rounds for the cold read and for task reviews; at the limit Forge asks for one more round, split or accept; fixes keep one round.**
4. **skill.md and brief.md describe the skip and the settings, and tell agents to use the skip only when a person asks.**
5. **Tests cover a new client repo and an existing repo adopted on an earlier release.**

## Risks

Risks: none one-way. Each part reverts with its pull request. Nothing is deleted, no data changes and no new vendor is added.

Trade-off: an agent can pass the skip without a person asking. Forge cannot tell a person from an agent, and it does not check that the name is real. The guard is the written rule in the guide and the worker brief, and the name and reason that show on the pull request, so a wrong use can be seen and traced. Forge's `forge stop` command refuses a worker's run; this plan adds no such refusal, because the owner chose the written rule. It is a few lines if you want it later.

Trade-off: a skipped item merges without any model look. Tests, CI and the design checks still run, so only what a model alone would catch (a logic gap, a missing case) can reach the default branch on a skipped change. This is what the owner chose for small changes.

Trade-off: the skip is refused for good once a review has blocked the item, even after the worker fixed it and a later round is clean. The planner read "an earlier round with blocking findings" that way, so the skip cannot be used to avoid a second look at a problem that was found. A person who still wants to go on can accept the findings with the step that exists today, `--resolve accept`.

Trade-off: a skip covers the commit it was given for. A later commit gets a full model review, over the whole branch, unless a person skips again. The skip is not kept as a standing setting for the item.

Trade-off: with one round for a cold read or a task review, Forge stops and asks the owner after the first round that still has open notes below P0. The team is asked more often and fewer problems are found before the owner is asked. A P0 note still keeps the loop going, as today.

Trade-off: the cold-read setting covers every cold read, not only a story's plan. Specs and decisions use the same code, so splitting them would add a second setting.

Trade-off: the board's activity line says "Review clean" for a skipped item, as for any clean review, because the owner asked that a skipped item count as ready in the same way. The pull request, the close output and the saved record say it was skipped, and by whom.

### New and existing repos

- **New repos** (`forge init`, `forge init --starter`, `forge init --starter python`, adoption): the skip option, the two settings (default two, no line in `forge.toml`), the guide and brief text and the decision work from the first close. A bad value is refused at once.
