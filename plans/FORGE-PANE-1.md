# /forge opens a small live pane of what is running on this laptop

3 parts · Risks: none one-way · New moving parts: none

## What changes for you

- When you type /forge in Claude Code, a small live pane opens. A pane is a small window that Claude Code shows beside the chat, or above the prompt when the window is narrow, and keeps up to date. It opens every time, at any window width, in the terminal and in the desktop app. (Source: your decision, 13 Nov 2026)
- The pane shows only what runs now on this laptop: builds, tests and reviews. They show in the order they started, under the headings Building, Tests and Review. A heading with no runs does not show. Each run shows its round and how long it has run, and the time counts up each second. A build also shows its current step when Forge knows it, for example "editing close.py". A run that waits for a free place says so. A run from another repo shows the name of that repo after its title, for example "Show late orders in shop-app". When nothing runs, the pane says "Nothing is running." The pane is not the board: it shows no totals, no finished work and no next command. (Source: your decision, 13 Nov 2026)
- One line at the top says if anything needs you, for example "Nothing needs you." or "Show late orders has a question for you." The line reads only files on this laptop, so it is fast. It shows two cases: a worker asked you a question, or Forge stopped an item and waits for your choice. It does not show a plan that waits for your approval, a pull request that waits for your merge, or a failed full test run, because these need GitHub or a slow check. The agent still tells you about them in the chat. (Source: your decision, 13 Nov 2026, for the line; the two cases are the planner's choice; confirm)
- From the pane you can open the output of a run, or stop a run. Before a run stops, the pane asks you, as today. (Source: your decision, 13 Nov 2026: the mock-up keeps these two buttons)
- The Claude desktop app shows more than the terminal, with the same words in the same order. At the top, two meters show how many places are in use, "Builds and reviews" and "Tests", for example "3 of 4" with a bar. A soft banner shows when something needs you. Each run is a card with a dot (filled when it runs, hollow when it waits), its time on the right, small tags for the round and the model (for example "Round 3" and "Sonnet") and the current step in code type. A test run shows a progress bar. The card that you select shows "LATEST OUTPUT" with the last three lines that the run wrote, and the two buttons. These three lines are the run's own words, so they show what the run printed. The terminal shows plain lines, with no meters, tags, bars or output lines. The richer drawing needs Claude Code 2.1.299 or later; an older desktop app shows the plain lines. (Source: your decision, 13 Nov 2026: "what about claude desktop electron app, you can style more", then "Richer still" and "Yes, go on with this")
- You choose when the pane opens. This is your own option, not a setting of the repo. It has two values: "typed", where the pane opens only when you type /forge, and "always", where the pane also opens by itself when a session starts in a Forge repo. You change it in Claude Code's settings menu (/config). Claude Code lets a pane open by itself only in a wide window: 144 columns or more in the terminal, or 110 after you opened the pane once. The rule for the desktop app is not written down. In a narrower window, type /forge. We propose "typed" as the default. (Source: your change, 13 Nov 2026; the default is the planner's choice; confirm)
- Forge's guide is a skill named "forge" in every client repo. A skill is a set of instructions that the agent loads when it needs them. The guide gets the new name "forge-guide", for Claude Code and for Codex, so that /forge is free for the pane. The agent finds and uses the guide as before. (Source: your decision, 13 Nov 2026, for a new name; the name "forge-guide" is the planner's choice; confirm)
- These parts go away for now: the agent turns that Forge events started, the line above the prompt, the board copy in the pane, the stage chains and the next-command button. The machine-readable form of the next-step report also goes, because only the old pane read it. The board page does not change. (Source: your decision, 13 Nov 2026. You said to remove the machine-readable report only if nothing else reads it, and nothing else does)
- A new client repo gets the guide with its new name at setup, and the pane works at once. An existing client repo gets the change when it upgrades Forge and syncs: Forge removes its own old guide files, adds the new ones and changes no other file. Files that a team added to the old guide folder stay. A session that was open during the upgrade needs a restart before /forge opens the pane. In a repo that has not upgraded yet, /forge still opens the old guide, and a short note at session start says why; with the option "always", the pane still opens by itself in a wide window. If old guide files stay after an upgrade, the setup check names them and its repair removes them. (Source: the planner's choice; confirm)
- This adds no model call. Model cost: none. While the pane is open, it asks Forge for new data every 3 seconds. Today one such read takes about 0.12 seconds of processor time (measured on this laptop on 13 Nov 2026, before the new needs-you check). In the desktop app the pane also reads the last lines of the selected run's output at each read, which takes a few thousandths of a second (estimate). While the pane is closed, it reads nothing.

## Why

Today /forge never opens the pane in a Forge repo. When a session starts, the pane asks Claude Code for the name /forge. The guide skill already has that name, so Claude Code refuses it, and the rest of the pane's start step does not run. The pane says "Loading Forge…" for the whole session, and /forge opens the guide. The tests did not see this, because they used a stand-in that always accepts the name. Behind that, the pane read the whole board every 10 seconds. In Forge's own repo one read takes about 16 seconds and prints 14 MB, more than a pane can take (4 MB). Forge's short machine report takes 0.18 seconds and 3 KB.

Today's workaround is to open the board page or to ask the agent. The cost: you cannot see at a glance what runs on your laptop, how long it has run, and whether it waits for you.

## Done when

1. **Typing /forge opens the pane every time, at 80 and at 200 columns, in the terminal and in the desktop app; with the person's option set to always, the pane also opens by itself when a session starts in a Forge repo in a window of 144 columns or more; and a real Claude Code session's log shows that /forge was accepted and that no start step was skipped, checked with Claude Code's real name rule and not with a stand-in.**
2. **The pane shows its first content in under 300 ms in Forge's own repo and in a new repo, its start step adds under 50 ms to session start and waits for no command, the word "Loading" never shows after the first content, and when Forge is missing or fails the pane keeps the last rows and adds one line that says how old they are.**
3. **The pane lists every build, test and review that runs on this laptop in the order they started, under Building, Tests and Review, each with its round and time and with the repo's name on rows from another repo, keeps the order of the rows that stay at each refresh, starts with one line that says whether anything needs you, and uses the same words for each run in the desktop app, in the terminal and in the text reply, with no IDs, no "unknown", no "0s", no empty values and no emoji in Forge's own words.**
4. **Forge answers the pane in under 300 ms and in under 20 KB in a repo with over 1,000 rows and in a new repo, and with the pane open for 10 minutes Forge's reads use under 10% of one processor core.**
5. **After setup in a new repo, and after upgrade and sync in an existing repo, Forge's guide skill has its new name for Claude Code and for Codex, no skill owns /forge, the team's own files stay, and only Forge's own files change.**

## Risks

Risks: none one-way. Each part reverts with its pull request. No data changes. In a client repo the old guide files go away only through the sync change that the repo's own pull request carries.

Trade-offs, in plain words:
- A script outside Forge that reads the machine-readable next-step report stops working. We found no such script.
- The needs-you line does not show approvals, merges or a failed full test run (see above).
- A build that runs as a subagent of your Claude session shows its round and time, but no current step: Forge does not see the steps of that subagent.
- A review shows its round and time, but no step: the review tool's own lines can hold IDs.
- The desktop app's "LATEST OUTPUT" lines are the run's own words, as the run wrote them, so they can hold IDs or file names. Forge does not change them.
- The pane cannot ask Claude Code whether the desktop app is light or dark. Text and lines use Claude Code's own theme colours, so they follow your theme. The bars and the soft fills use colours chosen to work in both; nobody has seen them in dark mode yet.

Not known until it is seen on screen:
- How the pane looks in the desktop app, in light and in dark mode, and whether the desktop app opens it by itself at session start. Its width rule is not written down.
- Which Claude Code version the desktop app runs. Its copy was 2.1.286 when the report was written; below 2.1.299 the desktop app shows the plain lines.
- Whether the times keep counting while the agent works on a turn. Claude Code's notes say that its timers run between turns.
- Windows, WSL, VS Code and phones were not checked.

### Decisions

- **Order of parts.** DATA (Python, additive) and RENAME run at once; they share no file. PANE waits for both: it reads DATA's fields and edits the guide copies that RENAME moves. The old mod keeps working on `forge next --json` until PANE removes both together.
- **The data contract (DATA pins it).** `forge lanes --json` keeps every field it has today and adds: top-level `repo_root` (the main checkout of the current folder as a POSIX path, from `main_checkout(Path.cwd())`, or `null` outside a git repo), top-level `needs_you` (the top line, a whole sentence, below), top-level `busy` (`true` when `_load_per_core()` is at least `LOAD_LIMIT` or available memory is below `memory_floor`, the admission rule in `_wait`), and per entry `step` (string or `null`). Rows: entries of every release show (remove the `version` filter from the rows; places and admission stay as they are); an entry with neither `started_at` nor `joined_at` is left out. The text form of `forge lanes` does not change. No new command.
- **Step (DATA).** For an entry of kind `work`, `worker` or `read` with an `item` and a `started_at`, read `<repo_root>/.git/forge/progress/*.json` once per repo (ponytail: the standard `.git` folder; a repo with a separate git folder shows no step), keep records whose `progress.item` is the entry's item, that have a `step`, and whose `progress.at` is at or after the entry's `started_at`; take the newest. Shorten it: `editing <path>` and `reading <path>` keep the file's base name (`editing close.py`); `running <command>` keeps the program's base name (`running pytest`, `running git`); other phrases stay. Reviews and tests get `null`. Claude session subagent rounds have no record, so `null`.
