### One brief and proportionate scrutiny

Use the existing task plan as the current brief: behavior, boundaries, owner, checks and rulings. Main presents the recovery amendment with recommendation, tradeoff, consequence and concrete artifact, but creates no new decision record. Lean records the correction/reason/technical classification/authority in the current brief, saves the new digest so stale approval drops, then bootstraps the concrete revision once with actual developer identity/time without claiming a new answer or reread. Material intent, scope, permission, migration, security, lifecycle, ownership or missing authority still requires display and explicit approval. The existing classifier remains authoritative: task contracts assign enduring documentation to the task owner and review enforces that ownership, while `docs/`, `plans/`, `prototype/`, `.gstack/`, and named repository metadata remain orchestration surfaces rather than acquiring a phase-dependent hook lock. Accepted0064 controls execution: an unanswered required question pauses the addressed task/artifact and every causally affected contract; separately owned dependency-ready unaffected work continues, while missing or canceled answers grant no authority. The recorded `Wait for all` answer governs only cooperative developer/host-directed coordinator transfer; it does not pause unrelated work or create a fencing claim.

Lean adds optional explicit `--context-file` only to `./forge grill run`; no other Forge command consumes it. The griller composes the normal authoritative artifact first and appends the selected file only as clearly delimited untrusted supplemental context. The path may be inside or outside the repository. Walk the absolute path without resolving through a link and refuse a symlink or Windows reparse point at any ancestor or leaf. Open the leaf once with the platform's no-follow/reparse-safe file-handle primitive, require the opened handle to be a regular file, and require the pre-open path identity, opened-handle identity, and post-read path identity to match; replacement or disappearance refuses. Stream that one handle once into an immutable UTF-8 byte snapshot while computing its SHA256 and byte count in memory, then launch only that captured snapshot. The context snapshot security invariant is read/write/delete accessible only to the effective current user and the launched same-user process. On POSIX, store captured bytes in a randomized regular single-link `0600` file beneath a dedicated current-user-owned `0700` transient directory, with no linked ancestor or leaf. On native Windows, create the transient directory and file with inheritance disabled and a protected DACL that grants access only to the current user SID; reopen and verify the actual owner and DACL before launch and before stale cleanup. Any extra allow ACE, unverifiable ACL, reparse point, link, owner drift, identity drift, or same-user mismatch refuses unchanged. Delete the transient after the terminal launch result is published. Durable logs/evidence retain only whether context was supplied, its byte count, and a random opaque context ID—never source path, content digest, or context bytes. Recovery deletes a stale transient only when ownership, DACL or POSIX mode, type, link/reparse status, exact directory boundary, and launch/context filename identity all match; otherwise it refuses unchanged. The file cannot alter primary artifact/gate/task identity or authority. Missing, linked/reparsed, replaced, non-regular, or non-UTF8 input refuses, with no search, reopen, repo-only root, or truncation. The local allocation safeguard is the fixed `8,388,608` UTF-8-byte griller limit; the installed model/component limit must also be discoverable in UTF-8 bytes, otherwise the context-file launch refuses and names the unknown limit. The required count covers the exact primary brief, delimiter/framing, and captured context bytes. A full input that fits the smaller limit is supplied unchanged. Because one grill gate has one cold read, `forge grill run` never partitions the artifact or its context; an oversized complete framed input refuses with required bytes and both limits. Any future partitioned consumer requires a separate approved capability and cannot satisfy a grill gate.

After Shared ships, each successful structured call gets one fresh event ID and zero-based question index. A multi-question call is atomic for authority: every question must return one nonblank answer; cancellation, omission, or failure of any question records no eligible event and makes every partial answer from that call unusable. Eligibility binds runtime, session, exact story/gate/task scope, current input digest, requiredness, question, ordered options, and the exact nonblank submitted answer. A free-form answer outside the offered labels is valid and preserved verbatim; choosing a label also preserves that exact label. One pass consumes each question once; Decision0067 and Decision0073 permit reuse only when re-recording the same gate for the same story and task and the question input digest still equals the recorded artifact. Optional non-gate questions cannot satisfy a gate. If an answer changes an approval-bound artifact, the earlier round remains audit context but cannot authorize the changed bytes. Its normal decision or approval independently binds the final revision, and the final grill uses a fresh eligible round or the independently ledgered empty-frontier route; neither claims the earlier question covered the final bytes. No revision-mapping protocol or new authority ledger is added. Lean eliminates mandatory round floors for its native approval flow and independently records no-human-frontier proof after one successful ledgered cold read with full disposition. Shared keeps broader structured-question and journey work. Anti-loop binding: cold proof binds the exact original input it reviewed; ordered one-to-one finding/resolution/source dispositions plus explained amendments bind that cold input to the final artifact digest; final human approval binds the final digest. The completed requirements cold-read adds three exact dispositions to that bridge: strengthen context snapshot security with same-user access and native Windows DACL proof; define independent migration coverage with a separate raw no-follow directory-entry walk and exact once classification comparison; qualify preservation with clean-target dirty refusal, no `--force` bypass, project-owned settings/profile preservation, and byte/hash-matching Forge-owned replacement only. Never claim the cold reader saw amended bytes, never require a second cold model call solely because resolving findings changed them, and refuse any unexplained out-of-disposition change.
