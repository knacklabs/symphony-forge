# Builds and tests run on separate cloud machines when the laptop is full

3 parts · Risks: sign-ins and GitHub write access stay in a cloud machine at an outside company; boxes that a developer turns off are gone for good · New moving parts: one outside company (agent37), one small provider interface

## What changes for you

In this plan, a "box" is a cloud machine that a company rents out by the hour. That company is the "provider". The first provider is agent37.com.

- A repo names one provider in its settings file. The team uses its own account at that provider and pays it directly. Forge talks to each provider through one small, shared set of steps, so a second provider is a small addition later. (Source: your decision of 12 Nov 2026)
- agent37 is the first provider, because it costs least. instabox.sh comes in a later story, and Mainline when its box service exists. (Source: your decision of 12 Nov 2026)
- Boxes are off in every repo. The agent turns them on for a repo only after you agree, in a small settings change. A new client repo gets boxes off at setup. An existing client repo also has boxes off after it upgrades and syncs; its settings and its work do not change. Both get the new steps in Forge's guide. (Source: your decision of 14 Oct 2026, kept on 12 Nov 2026)
- The laptop goes first. Builds and test runs use the laptop's free places as today. When a build round or a test run would wait in line for the laptop, it starts on a box at once. A box run does not come back to the laptop when a place frees. (Source: your decision of 12 Nov 2026)
- Both build rounds and test runs move to boxes, so more work reaches a ready pull request at the same time. (Source: your decision of 12 Nov 2026)
- Each developer has one kept box for each repo. The kept box holds the developer's sign-ins and the installed tools. Each run starts on a fresh copy of the kept box, and Forge deletes the copy when the run ends. (Source: your decision of 12 Nov 2026)
- Setup happens once per developer and repo. The agent asks Forge to make the kept box. The developer then opens the box's terminal and signs in there to Claude Code, Codex and GitHub, with their own accounts. Forge never sees, keeps or carries these sign-ins. A model key that the developer puts inside the box is the other allowed way. (Source: your decision of 12 Nov 2026)
- The developer keeps their own agent37 key on the laptop, in the shell, and Forge reads it only from there. Forge does not write it to any file. (Source: the planner's choice; confirm)
- Only committed code goes to a box. Files that git ignores stay on the laptop. At setup, the agent lists the ignored settings files that tests need and asks the developer about each one. Forge copies a file into the kept box only after a yes for that file, and every copy then has it. (Source: your decision of 12 Nov 2026)
- The box pushes the builder's commits to the work's branch on GitHub with the developer's own GitHub sign-in. The laptop then takes these commits into its own copy of the work. (Source: your decision of 12 Nov 2026)
- The model review and the cold reads stay on the laptop. (Source: your decision of 12 Nov 2026)
- Repos whose builders are subagents of a Claude Code session: a subagent of the laptop session cannot work on another machine. So a build round that goes to a box runs Claude Code inside the box as its own program, with the developer's sign-in there. The session does not start a subagent for it, and the round does not show in the session's list of agents. The agent keeps the build command open until the round ends. Rounds with a free laptop place still run as session subagents. (Source: the planner's choice; confirm)
- A box run shows in the machine view as an ordinary row with the words "in a box" and its minutes. The stop command ends a box run and deletes its copy. (Source: your decision of 14 Oct 2026, kept on 12 Nov 2026)
- When the provider fails, or a run cannot go to a box, the run waits in the laptop's line and Forge says why in one line. Before a run goes back to the laptop, Forge deletes its copy, so a copy never pushes work after that. (Source: your decision of 14 Oct 2026, kept on 12 Nov 2026)
- Spend limits stay in the provider's own dashboard. Forge adds no limit of its own. (Source: your decision of 14 Oct 2026, kept on 12 Nov 2026)
- To turn boxes off, the agent changes the repo's setting back to off, and each developer tells their agent to delete their boxes. Forge deletes the kept box and every copy of it, then says what it deleted. (Source: your decision of 14 Oct 2026, kept on 12 Nov 2026)
- Each box has 4 processors, 8 GB of memory and 30 GB of disk, on agent37's machine type that can run Docker, so tests that need Docker work. (Source: the planner's choice; confirm)
- The kept box is stopped between runs, so it costs only its disk. (Source: the planner's choice; confirm)
- The developer picks the box's region (United States, Europe or India) at setup. The default is the United States, the one region where agent37 offers every machine type. (Source: the planner's choice; confirm)
- Design rounds (work on screens) stay on the laptop, because they need a browser and screen checks that a box does not have yet. (Source: the planner's choice; confirm)
- A build round in a box always starts a new conversation with the full brief. Nobody can send it a note while it runs. If the builder needs an answer, it asks at the end, as today. (Source: the planner's choice; confirm)
- If a builder in a box leaves changes that are not committed, Forge asks it once to commit, as on the laptop. (Source: the planner's choice; confirm)

The machine type that runs Docker costs 2.5 times for processors and memory. So one copy costs about $0.034 for each hour it runs. A 20-minute test run costs about one cent. Forty copy hours in a month cost about $1.40. Design: none (no new screen; a box run's row in the machine view gets the words "in a box").

## Why

Every build round and every test run waits for one of the laptop's few places. On 11 Oct 2026 Forge's own repo had more work than one laptop can carry: the load reached 211, local tests timed out, and items spent 17.5% of their time in line. Since then the coordinator starts less work at once. The time in line fell to about 1%, but work that could run side by side now does not start at all.

Today's workaround: the agent starts fewer builds and test runs at once, and the rest waits. The cost is time from an idea to a ready pull request. A fast build does not help when its tests wait in line, so both build rounds and test runs must move. How much faster work gets ready is not measured yet.

## Done when

1. **With boxes on, a test run that would wait for a place on the laptop starts at once on a fresh copy of the developer's kept box, and its result reads the same as a laptop result.**
2. **With boxes on, a build round that would wait for a place on the laptop starts at once on a fresh copy, the box pushes the builder's commits to the work's branch, and the laptop's copy of the work then has them, also in a repo whose builders are subagents of a Claude Code session.**
3. **A developer sets up one kept box per repo once: Forge makes it, the developer signs in there to Claude Code, Codex and GitHub, and Forge copies only the ignored settings files that the developer approved one by one, and never reads a sign-in.**
4. **A box run shows in the machine view as an ordinary row marked "in a box" with its minutes, and the stop command ends it and deletes its copy.**
5. **When the provider fails or a run cannot go to a box, the run waits in the laptop's line and Forge says why in one line.**
6. **Boxes are off in every repo until the repo turns them on, and when a developer turns them off, Forge deletes that developer's kept box and every copy of it and says what it deleted.**

## Risks

These steps are sensitive or cannot be undone:

- The kept box holds the developer's sign-ins to Claude Code, Codex and GitHub, at agent37, an outside company. Anyone who gets into that box, at agent37 or through a fault, can use them. Forge never reads them, but it cannot protect them inside the box.
- The developer's GitHub sign-in can write to every repo the developer can reach, not only this one. A builder in a box can use all of them. You chose this knowingly on 12 Nov 2026.
- The box pushes commits to GitHub before the laptop sees them. The review and the tests on the laptop still run before any merge.
- An ignored settings file that the developer approves can hold real keys. It goes to agent37 and stays in the kept box and in every copy until the boxes are deleted.
- When a developer turns boxes off, Forge deletes the kept box, the sign-ins and copied files in it, and every copy, also the copy of a run that has not ended. Work in that copy that the box did not push is lost. This cannot be undone. agent37 keeps deleted data in its backup storage for seven days, then removes it.
- A copy whose laptop program was killed keeps its cost until the developer turns boxes off or deletes it in agent37's dashboard.
- agent37 is a new outside company for Forge. The setup uses only the steps that the model companies allow: the developer signs in to the unchanged Claude Code and Codex with their own accounts.
