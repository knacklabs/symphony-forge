## Why

Every test run waits for one of the laptop's few places. On 11 Oct 2026 Forge's own repo had more work than one laptop can carry: the load reached 211, local tests timed out, and items spent 17.5% of their time in line. Measured over 86 items from 11 to 14 Oct, local tests and the wait for the test line took about 22% of item time, and build rounds about 8%. So test runs move first.

Today's workaround: the agent starts fewer builds and test runs at once, and the rest waits. The cost is time from an idea to a ready pull request. How much faster work gets ready is not measured yet.

## Done when

1. **With boxes on, a test run that a builder or the close step starts, and that would wait for a place on the laptop, starts at once on a fresh copy of the developer's kept box, and its result reads the same as a laptop result.**
2. **A developer sets up one kept box per repo once: Forge makes it, the developer approves the GitHub sign-in for it in the browser, and Forge copies only the ignored files that the developer approved one by one, and never reads a sign-in.**
3. **A box run shows in the machine view as an ordinary row marked "in a box" with its minutes, and the stop command ends it and deletes its copy.**
4. **When the provider fails or a test run cannot go to a box, the run waits in the laptop's line and Forge says why in one line.**
5. **Boxes are off in every repo until the repo turns them on, and when a developer turns them off, Forge deletes that developer's kept box and every copy of it and says what it deleted.**

## Risks

These steps are sensitive or cannot be undone:

- The kept box holds the developer's GitHub sign-in, at agent37, an outside company. Anyone who gets into that box, at agent37 or through a fault, can use it. Forge never reads it, but it cannot protect it inside the box.
- The developer's GitHub sign-in can write to every repo the developer can reach, not only this one. You chose this knowingly on 12 Nov 2026.
- An ignored settings file that the developer approves can hold real keys. It goes to agent37 and stays in the kept box and in every copy until the boxes are deleted.
- When a developer turns boxes off, Forge deletes the kept box, the sign-in and copied files in it, and every copy. This cannot be undone. agent37 keeps deleted data in its backup storage for seven days, then removes it.
- A copy whose laptop program was killed keeps its cost until the developer turns boxes off or deletes it in agent37's dashboard.
